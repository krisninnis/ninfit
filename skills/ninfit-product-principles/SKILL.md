# NinFit Product Principles

## Purpose

Use this skill whenever designing or implementing NinFit product behaviour, user journeys, rewards, fitness interactions, mascot systems, AI features, or engagement mechanics.

NinFit is a premium fitness companion where real fitness progress drives a long-term creature-collection and progression game.

Core relationship:

**FITNESS IS THE PRODUCT. THE GAME IS THE EMOTIONAL REINFORCEMENT LAYER.**

Product North Star:

**CALM BY DEFAULT. ENERGY EARNED. SHOWING UP CELEBRATED.**

## Non-negotiable principles

- Fitness comes first.
- Give the user one obvious next action.
- Personal progress matters more than comparison with others.
- Social features are optional.
- Calm is the default emotional state.
- Energy and celebration are earned.
- Partial completion counts.
- Planned rest is part of the programme.
- Do not use guilt, shame, punishment, or broken-streak pressure.
- Do not use red as a generic failure state.
- Health data is private by default.
- Missing data remains missing.
- Never fabricate health, fitness, activity, nutrition, or sensor readings.
- Never diagnose.
- Preserve data provenance.
- Sustainable activity must beat overtraining.
- Permanent mascot progress is never removed due to inactivity.
- Mascots never die, starve, or become sad because the user missed exercise.
- No pay-to-win.
- No paid loot boxes or paid random eggs.
- Prestige must be earned, not purchased.
- Rest, recovery, holidays, illness, injury, and life interruptions must be treated without judgement.

## Product design rule

Before approving a feature, ask:

1. Does this help the user sustain real fitness?
2. Does it preserve truth and provenance?
3. Could it pressure the user into unsafe or excessive activity?
4. Could it make inactivity feel like failure?
5. Does the game reinforce fitness rather than compete with it?
6. Is the next user action obvious?
7. Can a beginner or returning user understand it without intimidation?

If a feature fails these checks, redesign it before implementation.

## Engagement design

Good NinFit engagement:
- celebrates showing up
- notices consistency
- recognises personal improvement
- supports planned recovery
- welcomes return after absence
- creates emotional attachment through shared history
- rewards sustainable behaviour

Bad NinFit engagement:
- punishment for missed days
- loss of permanent progress
- forced streak maintenance
- generic escalating activity targets
- social pressure
- manipulative scarcity
- pay-to-win
- hidden health-data exposure

## Return-after-absence rule

One missed workout should normally do nothing.

If a meaningful pattern of lower engagement develops, NinFit may use a gentle context check-in.

Preferred return language:

**“Good to see you.”**

Never summarise absence as a failure count.

## Competition and prestige

Prestige should primarily represent:
- consistency
- personal improvement
- long-term engagement
- meaningful milestones
- Champion progression
- Legacy history

Absolute athletic performance must not be the only or dominant prestige path.

## Scope discipline

Do not implement an idea merely because it was discussed in product Q&A.

Product decisions become implementation only through an explicitly authorised milestone or task.
